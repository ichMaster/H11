# v0.8 — GitHub Issues

Issues for phase **v0.8 — Prototype-0 hardening** (version **v0 — Prototype 0: one deck, on the
device, at 60 fps**), derived from the per-phase Tasks in [ROADMAP.md](../ROADMAP.md) (§v0.8) and the
contracts in [ARCHITECTURE.md](../ARCHITECTURE.md) (§Contracts, §Failure modes, §Acceptance and
testing). This file is scoped to a single phase; IDs start the project's sequence
(**H11-001…H11-014**).

Prototype 0 works and its gates are green, but a multi-agent review confirmed 39 defects — five of
them visible to a player in every run, nine on failure paths that will bite once the SDLC pipeline
runs unattended. This phase clears both tiers before anything is built on top. It extends no seam; it
makes the existing ones honest, and it hardens the four acceptance gates themselves so every later
phase can trust them.

## v0.8 — Prototype-0 hardening

### H11-001 — Validate deck geometry at load instead of with a stripped assert

**Description:**
`_parse` guards equal row lengths with `assert`, which is removed from release builds. A ragged deck
therefore produces silent collision holes on the device and nowhere else. Touches `scripts/level.gd`.

**What needs to be done:**
- Replace the row-length `assert` with the same treatment the missing-file case already gets:
  `push_error` naming the offending row index and its length, plus a `Game.say` message.
- Refuse to build geometry from an invalid grid rather than building a broken one.
- Extend the check to the other invariants ARCHITECTURE names: exactly one `P`, every character known
  to `WALL_TEX` or `WALKABLE`.

**Dependencies:** None

**Expected result:**
A malformed deck fails with a named reason in a release build instead of producing a level the player
can walk through a wall of.

**Acceptance criteria:**
- [ ] A fixture deck with a short row, two `P`s, or an unknown character each fail with a distinct message
- [ ] The failure is visible in an exported build, not only in the editor
- [ ] **Gate:** `--smoke` on the real deck stays green; a new assertion covers the ragged-row fixture

### H11-002 — Smoke test must exit 1 on a structural failure, never hang

**Description:**
When a map assumption breaks, `_run_smoke` continues past the failed check and blocks on a later
`await` that never resolves, so CI waits forever instead of failing. Touches `scripts/debug_drive.gd`.

**What needs to be done:**
- After each structural check (`locked door exists`, `a live mutant found`, `player spawned`), bail
  out immediately on failure: print the remaining checks as FAIL and quit with code 1.
- Add a wall-clock watchdog so any future await cannot hang the run.

**Dependencies:** None

**Expected result:**
A broken deck makes `--smoke` exit 1 within seconds, with a named failing assertion.

**Acceptance criteria:**
- [ ] A deliberately broken fixture deck makes `--smoke` exit 1, not hang
- [ ] The watchdog fires with a message naming the last check reached
- [ ] **Gate:** `--smoke` on the real deck unchanged at 16/16

### H11-003 — Door slab shows a 1/6 crop of its texture

**Description:**
The slab is a `BoxMesh`, whose UVs are a 3×2 per-face atlas, but `door.png` is authored as one full
door face. Every face therefore shows a magnified sixth of the texture — the centre seam, the second
porthole and the OPEN/LOCK panel that distinguishes a locked door never appear. Touches
`scripts/door.gd` (or `scripts/level.gd`) and `scenes/door.tscn`.

**What needs to be done:**
- Set `uv_scale = Vector2(3, 2)` on the door materials, which works because the sampler is
  `repeat_enable`; or replace the slab with explicit quads carrying authored UVs.
- Confirm both `door` and `door_locked` read correctly, including from behind.

**Dependencies:** H11-002

**Expected result:**
A door shows the whole authored door, and a locked door is distinguishable from an unlocked one at
corridor distance.

**Acceptance criteria:**
- [ ] Both door states show jambs, both portholes, the seam and the control panel
- [ ] The locked variant is distinguishable at 8 m in the dark
- [ ] **Gate:** `--drive` frames read back showing a correct door; `--smoke` green

### H11-004 — Killed mutants stay permanently red

**Description:**
`hit()` sets `_flash = 0.12` before the killing blow calls `_die()`; once the state is `DEAD` the
decay is unreachable, so `_apply_depth_shade` takes the flash branch forever and the corpse renders
`Color(1.0, v*0.3, v*0.3)` — a constant red channel that also ignores distance darkening. Touches
`scripts/enemy.gd`.

**What needs to be done:**
- Clear `_flash` in `_die()`, or decay it in the `DEAD` branch before the early return.

**Dependencies:** H11-002

**Expected result:**
A corpse is shaded by distance like every other sprite.

**Acceptance criteria:**
- [ ] A killed mutant's modulate equals `Level.depth_shade()` within one frame of the death animation ending
- [ ] **Gate:** a new `--smoke` assertion on the dead enemy's modulate; `--drive` frame shows a non-red corpse

### H11-005 — Ammo and keycard pickups render as medkits

**Description:**
`add_child` fires `_ready` synchronously, which stamps the sprite from the default `kind` before
`setup()` assigns the real one. Every ammo and keycard on the floor shows the medkit texture while
behaving correctly — and the player is told to find a red keycard that looks like a medkit. Touches
`scripts/pickup.gd` and `scripts/level.gd`.

**What needs to be done:**
- Apply the texture inside `setup()`, the way `door.gd` already applies its material; or call
  `setup()` before `add_child`.

**Dependencies:** H11-002

**Expected result:**
Each pickup shows its own sprite.

**Acceptance criteria:**
- [ ] Medkit, ammo and keycard each render their own texture on deck 1
- [ ] **Gate:** a new `--smoke` assertion comparing each spawned pickup's texture to its kind

### H11-006 — Floor and ceiling fog is evaluated at four corners

**Description:**
`depth_fade` is computed in `vertex()` and interpolated. That is right for 2×2 m wall quads and wrong
for two un-subdivided level-wide planes: a four-vertex plane samples the exponential at the four
level corners, so floor brightness tracks distance-to-corners rather than to the fragment, and the
ground reads ~2.5× darker than the wall bases it touches. Touches
`shaders/depth_shade_mip.gdshader`.

**What needs to be done:**
- Pass `varying vec3 view_pos` and compute `exp(-length(view_pos) * fog_density)` per fragment. The
  shader is used only by the two planes, so the extra per-pixel `exp` is confined to them.
- Do not change `depth_shade.gdshader`; walls stay per-vertex.

**Dependencies:** H11-002

**Expected result:**
The floor under the player is as bright as the wall bases beside it, and the gradient has no kink
along the plane's diagonal.

**Acceptance criteria:**
- [ ] Floor brightness at the player's feet is within one ramp step of the adjacent wall base
- [ ] No visible seam along the plane diagonal
- [ ] **Gate:** `--drive` frames compared against the pre-fix baseline; `--bench` on the device stays under 4 ms mean

### H11-007 — ambient.wav clicks at its loop seam every six seconds

**Description:**
The ambient bed is generated without matching its start and end, so the loop point is a hard
discontinuity — an audible click every six seconds for the whole run. Touches `tools/gen_sounds.py`.

**What needs to be done:**
- Cross-fade the tail into the head, or generate a whole number of cycles for every component so the
  seam is continuous by construction.
- Keep the module's RNG discipline: any new randomness uses a local `random.Random(seed)` so the ten
  other sounds stay byte-identical.

**Dependencies:** None

**Expected result:**
The ambient bed loops without a click.

**Acceptance criteria:**
- [ ] The sample-level discontinuity at the seam is below an audible threshold, asserted numerically
- [ ] The other ten WAVs regenerate byte-identically
- [ ] **Gate:** a seam-continuity check added to the acceptance set

### H11-008 — check_palette.py dies on a corrupt PNG instead of failing one file

**Description:**
A truncated or malformed PNG raises out of the decoder and aborts the whole run, so one bad file
hides the status of the other 32 — in a gate whose job is to report on all of them. Touches
`tools/check_palette.py`.

**What needs to be done:**
- Catch decode errors per file, report that file as FAIL with the reason, and continue.
- Keep the exit code non-zero when any file fails.

**Dependencies:** None

**Expected result:**
One corrupt asset fails one line; the other 32 are still reported.

**Acceptance criteria:**
- [ ] A deliberately truncated PNG yields one FAIL line and a complete report
- [ ] Exit code is 1
- [ ] **Gate:** `check_palette.py` on the real set still reports 33/33

### H11-009 — gen_assets.mjs writes an asset that failed its own alpha check

**Description:**
The generator reports a semi-transparent pixel and then writes the file anyway, overwriting good
committed art with output it just declared invalid — the size-mismatch path correctly skips, this one
does not. Touches `tools/gen_assets.mjs`.

**What needs to be done:**
- Skip the write on a failed alpha check, matching the size-mismatch path; or write to a temporary
  name and move into place only after every check passes.
- Make the run's exit code reflect any skipped asset.

**Dependencies:** H11-008

**Expected result:**
A generator bug can no longer destroy committed art.

**Acceptance criteria:**
- [ ] A function producing a semi-transparent pixel leaves the existing PNG untouched and exits non-zero
- [ ] **Gate:** a full regeneration still reproduces all 33 files pixel-for-pixel

A typo fails loudly.

### H11-011 — Deploy kills the game before the copy, so a failed copy bricks the run

**Description:**
`deploy_to_term35.sh` stops the running game and then overwrites the binary in place. If the copy
fails — network drop, full disk — the device is left with no running game and a truncated binary.
Touches `tools/deploy_to_term35.sh`.

**What needs to be done:**
- Copy to a temporary name first, verify it arrived whole, then stop the game and move it into place
  atomically.
- On a failed copy, leave the previous binary and the running game untouched and exit non-zero.

**Dependencies:** None

**Expected result:**
A failed deploy leaves the device exactly as it was.

**Acceptance criteria:**
- [ ] An interrupted copy leaves the old binary intact and the game running
- [ ] A successful deploy is unchanged from the caller's point of view
- [ ] **Gate:** a real deploy to the device succeeds and the game runs

### H11-012 — Sway scale restore is not crash-safe

**Description:**
`run_on_pi.sh` reads the desktop scale, sets 1 for the game, and restores it from an EXIT trap. A
SIGKILL, a power cut, or two concurrent launches lose the original value permanently, leaving the
desktop at scale 1 with text too small to read at arm's length. Touches `tools/run_on_pi.sh`.

**What needs to be done:**
- Persist the pre-game scale to a state file before changing it; restore from that file on the next
  launch if it still exists, so a crashed run self-heals.
- Guard against a second concurrent launch overwriting the saved value with 1.
- Degrade cleanly when `swaymsg` is absent.

**Dependencies:** H11-011

**Expected result:**
The desktop scale always comes back, whatever killed the game.

**Acceptance criteria:**
- [ ] `kill -9` on the game and a relaunch restores 1.25
- [ ] Two overlapping launches never persist 1 as the saved scale
- [ ] **Gate:** verified on the device, scale queried through `swaymsg` before and after

### H11-013 — Remote-deploy cleanup script can never kill the running game

**Description:**
The editor's Remote Deploy cleanup script matches the process by a pattern the running game never
has, so it always fails to stop it and the next deploy collides with a live process. Touches
`export_presets.cfg`.

**What needs to be done:**
- Match the process the way `deploy_to_term35.sh` does (`pkill -x` on the executable name).
- Note in the preset that the editor path skips the scale-1 correction `run_on_pi.sh` applies.

**Dependencies:** H11-011

**Expected result:**
The editor's Remote Deploy stops what it started.

**Acceptance criteria:**
- [ ] The cleanup script stops a running game on the device
- [ ] `deploy_to_term35.sh` behaviour is unchanged

### H11-014 — Mockup renderer hardcodes a fog value it claims to read from the game

**Description:**
`h11_frame.js` states it renders at `Level.FOG_DENSITY` but hardcodes 0.085, while the shipped value
is 0.025. Every mockup it produces is therefore darker at distance than the game, so comparing a
`--drive` frame against a mockup measures the wrong thing. Touches `tools/h11_frame.js`.

**What needs to be done:**
- Read the value from a single source, or default to the shipped 0.025 and print the value used in
  the render banner.
- Correct the comment that states the pixel size, which names a value the game does not use.

**Dependencies:** None

**Expected result:**
A mockup and a game frame are comparable.

**Acceptance criteria:**
- [ ] A regenerated mockup at the shipped fog value matches a `--drive` frame's distance falloff
- [ ] The renderer prints the fog value it used
