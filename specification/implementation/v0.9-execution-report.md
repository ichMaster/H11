## What the phase actually found

- **No `BTN_*` anywhere.** The open question the phase was built around — whether the buttons reach
  Godot as joypad input — answered no. That *removed* work from H11-016 rather than adding it.
- **The buttons collide with the development keyboard.** They send the same physical keycodes, so
  the two schemes cannot both be live. Resolved by two profiles chosen by `Game.on_device` — a
  decision the plan had not anticipated and the owner made mid-phase.
- **`_setup_input()` ran before `on_device` was assigned.** Reading the flag there would have handed
  the device the desktop profile silently. Found by reading the order, not by running.
- **`data/input.json` is not a Godot resource.** Without `include_filter` it would never have reached
  the device — this project's third encounter with that failure mode.
- **The suite proved less than it claimed.** `Input.action_press` drives the action, not the key, so
  the suite depends on the table registering actions, not on the bindings. Recorded in the code
  rather than overstated.
- **v0.8's watchdog caught a case it was not written for.** Removing the input table made `--smoke`
  fail by timeout instead of hanging; the timer was added for a ragged deck.

## Estimate vs actual

The roadmap predicted 5–7 issues and 10–16 size-weighted points. The decomposition produced **6
issues and 12 points**. Effort was lower than the S/M sizing implied, because the `BTN_*` answer
deleted a whole branch of H11-016 and three of the six issues were device-verification rather than
code.
